# 后端项目结构说明（模块化单体 + 轻量依赖管理）

## 一、总体设计

本项目采用：

- 模块化单体架构（Modular Monolith）
- 分层设计（router / service / repository / model / schema）
- 轻量依赖工厂（不使用重型 IoC 容器）

核心目标：

- 提高内聚
- 降低耦合
- 支持多人协作
- 支持后续演进

请求链路：

router → service → repository → model

------

## 三、核心目录说明

### core（系统基础设施）

- config：配置管理
- database：数据库连接与 SessionFactory
- security：认证与 JWT
- exceptions：统一异常定义
- response：统一返回结构
- logging：日志配置

说明：

- 数据库连接（engine）为全局单例
- Session 必须为请求级对象（通过 Depends 获取）

------

### common（公共抽象层）

- base_model：ORM 基类
- base_schema：序列化配置
- base_repository：基础 CRUD
- pagination：分页工具
- enums：统一状态枚举
- dependencies：权限控制
- utils：工具函数

------

### container（轻量依赖提供层）

职责：

- 统一依赖装配方式
- 提供 service / repository / 工具类访问入口

定位说明：

- container 不是重型 IoC 容器
- container 也不是“每次调用都重新创建对象”的纯工厂
- 默认采用模块级共享实例
- 复用的是对象实例与装配关系，不是请求上下文状态

适合放入 container 的对象：

- 无状态 Service
- 无状态 Repository
- 纯工具类

不放入 container 的对象：

- Session
- 当前登录用户
- 任何请求级上下文

------

## 四、容器实现约定

说明：

- `get_xxx()` 在这里表示“获取已装配好的依赖入口”，不是“每次新建一个对象”
- 默认返回模块级共享实例
- 只有在明确需要时，才单独设计真正的工厂函数

### repositories.py

```python
_user_repository = UserRepository()
_house_repository = HouseRepository()

def get_user_repository():
    return _user_repository

def get_house_repository():
    return _house_repository
```

------

### services.py

```python
_user_service = UserService(get_user_repository())
_house_service = HouseService(get_house_repository())

def get_user_service():
    return _user_service

def get_house_service():
    return _house_service
```

------

### tools.py

```python
_password_hasher = PasswordHasher()

def get_password_hasher():
    return _password_hasher
```

------

### 使用方式（FastAPI）

```python
@router.post("/")
def create(
    data: UserCreate,
    service = Depends(get_user_service)
):
    return service.create(data)
```

- 不包含业务逻辑

## 八、事务设计（关键约束）

事务统一在 service 层控制。

规则：

1. 所有跨表写操作必须在 service 层开启事务
2. repository 层禁止调用 commit / rollback
3. 单表简单操作可直接调用 repository
4. 多模块协作由主 service 控制事务

示例：

```python
def create_contract(db, data):
    try:
        contract_repo.create(db, ...)
        house_repo.update_status(db, ...)
        bill_repo.create(db, ...)
        db.commit()
    except:
        db.rollback()
        raise
```

## 九、重要模块约束

### search

- 不拥有数据表
- 不修改数据
- 只做查询与推荐

------

### statistics

- 不拥有数据表
- 只做聚合查询

------

### log

- 负责日志写入与查询
- 不参与业务流程

------

### notification

- 负责消息分发
- 不承载核心业务状态

------

### storage

- 负责文件处理
- 不耦合业务逻辑

------

## 十、设计原则

- 模块内聚
- 低耦合
- 单向依赖
- 公共能力下沉
- 状态统一使用枚举
- service 不保存请求状态
- session 必须请求级传递

------

## 十一、约束

- 不集中 repository
- 不设计复杂 BaseService
- 不在 repository 控制事务
- 不在 service 中保存状态
- 不在 container 管理 session

------

## 十二、扩展路径

阶段1：当前模块化单体
阶段2：模块内部细分
阶段3：抽离基础设施
阶段4：按模块拆分服务

说明：

- 不需要推翻结构
- 逐步演进

------

## 十三、总结

该结构具备：

- 清晰模块边界
- 稳定事务控制
- 合理依赖关系
- 可扩展架构

适用于中小型系统，并可作为大型系统演进基础。
